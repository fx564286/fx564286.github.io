# UI5-010 — 자동 사냥 UI 부분 갱신 및 렌더링 안정화

- **Task ID:** UI5-010
- **담당 섹션:** 5번 UI/UX
- **상태:** 독립 웹 UI 시연 구현·로컬 검증 완료. 실제 Core/서버 통합은 미완료.
- **변경 파일:** `game-uiux-section5-preview/index.html`
- **추가 테스트:** `game-uiux-section5-preview/tests/ui5-010-render-stability.cjs`
- **배포:** https://fx564286.github.io/game-uiux-section5-preview/?build=ui5-010

## 기존 결함
매 전투 시뮬레이션 공격마다 `render()`가 `app.innerHTML` 전체를 교체하여 캐릭터·7개 몬스터 SVG·내비게이션 DOM이 전부 재생성되었다. 대규모 공격 이벤트 집계 UI에 부적절한 리렌더링 비용과 포커스/연출 초기화 리스크가 존재했다.

## 수정
- 기존 화면 생성 API 및 GameTransport 명령 타입은 변경하지 않음.
- 전투 진행 중 `syncBattleView()`로 몬스터별 HP, 생존 상태, 캐릭터 HP/기력, 처치 수 및 전투 로그만 인플레이스 갱신.
- 웨이브 전환 등 유닛 구조가 실제로 변경되는 상황만 전체 화면을 다시 렌더링.
- 피해 연출: 180ms 빈도 상한 및 기존 임시 연출 노드 정리. 동시 피격 시각 효과가 무제한 생성되지 않도록 제한.
- 전투 계산은 기존 mock fixture 기반이며 실제 전투 코어로 오인하면 안 됨.

## ECC TDD 검증
- **RED:** 수정 전 Chromium 테스트에서 공격 1회 후 `battleRootStable=false, firstMobStable=false, navStable=false`; 테스트 종료 1.
- **GREEN:** 수정 후 같은 테스트에서 세 DOM identity 모두 true; 종료 0.
- **정식 회귀:** 320×720, 390×844, 1365×840에서 7마리, HP 동기화, DOM 유지, 캐릭터 확대, 전투 일시정지, horizontal overflow 0, 브라우저 예외 0.
- **전체 게임 진행:** 2-wave 자동 사냥, 메뉴 전환 중 상태 진행, 승리, 시연용 보상 지급 동선 통과.
- **시각 부하 검사:** Chromium 내 `battleImpact` 및 `syncBattleView` 2,000회 연속 호출 중 캐릭터/몬스터/내비게이션 노드 유지, 효과 노드 상한 2개. 프로덕션 APS 또는 서버 성능 검증 아님.
- **JS 구문 검사:** `node --check` 통과.
- **빌드/타입/일반 린트/커버리지:** 정적 단일 HTML 시연 프로젝트에는 해당 스크립트 미구성으로 미실시. 테스트 커버리지 수치는 산출하지 않음.
